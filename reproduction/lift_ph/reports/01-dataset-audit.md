# Lift-PH Low-Dim 数据集审计报告

## 1. 审计结论

审计状态：**PASS**

当前数据集满足 Lift-PH State BC 实验的使用条件：

- 数据来源与版本正确；
- 文件 SHA256 与预期值一致；
- HDF5 可以正常读取；
- 轨迹数和 transition 数正确；
- State BC 的输入、输出字段及维度正确；
- 未发现 NaN 或 Inf；
- 动作均在归一化控制范围内；
- train 与 valid 不存在轨迹交集；
- 数据记录的环境版本与本机 robosuite 版本一致。

这个 PASS 的含义是“数据完整性和训练前提通过检查”，不代表尚未训练的策略一定能获得高成功率。

### 为什么必须检查 SHA256

文件名相同不等于文件内容相同。下载中断、文件损坏或版本混用都可能留下同名文件。SHA256 是根据文件全部字节计算出的内容指纹；本地值与预期值一致，才有充分依据认为我们使用的是同一份数据。

数据集本体位于 `datasets/`，体积大且可以从官方重新下载，所以被 `.gitignore` 忽略。报告、脚本和配置体积小，记录了实验方法与证据，因此应该提交 Git。

## 3. 数据规模

| 指标 | 数值 |
|---|---:|
| trajectory 数 | 200 |
| transition 总数 | 9666 |
| 最短轨迹 | 36 transitions |
| 平均轨迹长度 | 48.33 transitions |
| 最长轨迹 | 64 transitions |

一条 trajectory（例如 `demo_0`）是一段完整示范。若它有 59 个时间步，则其中存有 59 个训练样本：

$$
(o_0,a_0), (o_1,a_1), \ldots, (o_{58},a_{58})
$$

一个 transition 是时间步 $t$ 上的一组记录，核心关系是：

$$
(o_t, a_t, r_t, d_t, o_{t+1})
$$

其中 $o_t$ 是当前观测，$a_t$ 是专家在看到该观测后给出的动作，$r_t$ 是奖励，$d_t$ 是完成标记，`next_obs` 保存执行 $a_t$ 后的下一时刻观测 $o_{t+1}$。

因此，9666 表示 200 条轨迹合计包含 9666 个时间步样本，不是 9666 个标量动作。每个时间步的动作是 7 维，所以动作矩阵总形状是 `(9666, 7)`，其中共有 $9666\times7=67662$ 个动作标量。

## 4. HDF5 结构

根节点包含：

- `data`：200 条示范轨迹及环境元数据；
- `mask`：训练、验证和不同数据量实验使用的轨迹名单。

每个 `data/demo_*` 至少包含：

| 字段 | 含义 | 典型形状（`demo_0`） |
|---|---|---:|
| `obs` | 执行动作前的可观测输入 | 多个 `(59, D)` 数组 |
| `actions` | 专家动作 | `(59, 7)` |
| `next_obs` | 执行动作后的下一观测 | 多个 `(59, D)` 数组 |
| `rewards` | 每个 transition 的奖励 | `(59,)` |
| `dones` | 每个 transition 的完成标记 | `(59,)` |
| `states` | MuJoCo 可恢复仿真状态 | `(59, 32)` |

`states` 是仿真器内部用于恢复场景的完整状态，不等于策略在部署时能够获得的观测。State BC 使用 `obs` 中明确选择的字段训练，不能因为 `states` 存在就把它偷偷加入策略输入。

## 5. State BC 的输入和输出

官方 State BC 模板选择四个观测字段：

| 输入字段 | 维数 | 含义 |
|---|---:|---|
| `robot0_eef_pos` | 3 | 末端执行器的 $x,y,z$ 位置 |
| `robot0_eef_quat` | 4 | 末端姿态四元数 |
| `robot0_gripper_qpos` | 2 | 两个夹爪关节各自的标量关节位置 |
| `object` | 10 | 方块位置 3、方块四元数 4、末端到方块的相对位置 3 |
| 合计 | **19** | 策略在一个时间步的低维输入 |

需要特别区分：

- `robot0_gripper_qpos` 的 2 维不是夹爪的二维 XY 坐标，而是两个夹爪关节的位置；
- 姿态观测使用 4 维四元数；
- 动作中的姿态增量使用 3 维旋转控制量，两者表示方式不同。

State BC 学习的映射是：

$$
\pi_\theta(o_t) \longrightarrow \hat a_t
$$

监督目标是同一时间步的专家动作 $a_t$，即学习 `(obs[t], actions[t])`，不是拿 `obs[t]` 去预测 `actions[t+1]`。

普通前馈 BC 训练不需要把 `next_obs` 作为策略输入。`next_obs` 对动力学学习、时序一致性检查或某些强化学习算法有用，但不能据此认为“只有长序列任务才需要它”。BC-RNN 需要的是按时间顺序组织的一段 `obs` 和 `actions`，也不等于直接把 `next_obs` 喂给策略。

### 7 维动作

| 动作维度 | 含义 |
|---|---|
| 0–2 | 末端位置控制：`delta_x, delta_y, delta_z` |
| 3–5 | 末端旋转控制：`delta_rx, delta_ry, delta_rz` |
| 6 | 夹爪命令 |

动作是输入到 OSC_POSE 控制器的归一化命令，允许范围为 $[-1,1]$。控制器再把归一化命令映射为物理位置或姿态增量。因此 `delta_y` 在专家数据中实际只出现于 $[-0.56,0.652]$，并不意味着它的合法控制范围变窄；它只说明专家在这批示范里没有用到整个允许范围。

夹爪命令只有两个取值：

- `-1`：打开；
- `+1`：闭合。

## 6. 动作分布

| 维度 | 最小值 | 均值 | 标准差 | 最大值 | 等于 -1 | 等于 +1 |
|---|---:|---:|---:|---:|---:|---:|
| `delta_x` | -1.000000 | 0.172476 | 0.259176 | 1.000000 | 1 | 10 |
| `delta_y` | -0.560000 | 0.005815 | 0.129825 | 0.652000 | 0 | 0 |
| `delta_z` | -1.000000 | -0.168830 | 0.493942 | 1.000000 | 20 | 883 |
| `delta_rx` | -0.150659 | 0.003080 | 0.022275 | 0.118636 | 0 | 0 |
| `delta_ry` | -1.000000 | 0.005131 | 0.063487 | 0.305093 | 1 | 0 |
| `delta_rz` | -0.517975 | 0.011491 | 0.083427 | 0.478234 | 0 | 0 |
| `gripper` | -1.000000 | -0.407614 | 0.913154 | 1.000000 | 6803 | 2863 |

这些统计说明：

- 所有动作都位于允许的 $[-1,1]$ 范围；
- 专家使用动作空间不同维度的频率并不均匀；
- `delta_z=+1` 出现较多，和 Lift 任务中的快速向上抬升行为相符；
- 夹爪是离散的开/闭命令，而其余六维为连续控制量；
- 是否碰到边界本身不是错误，但大量边界值值得在训练和 rollout 后继续观察。

这里的均值、分位数等是把所有轨迹的动作行拼接后做的描述性统计。这样做适合了解信号分布，但不能用同样方式随机拆分训练集和验证集。

## 7. reward 与 done

| 指标 | 数值 |
|---|---:|
| `reward == 1` 的 transitions | 1005 |
| `done == 1` 的 transitions | 1005 |
| 含 `reward == 1` 的轨迹 | 200 |
| 含 `done == 1` 的轨迹 | 200 |
| 末行 `reward == 1` 的轨迹 | 200 |
| 末行 `done == 1` 的轨迹 | 200 |
| 末行之前 `done == 1` 的 transitions | 805 |
| reward 为 1 但 done 不为 1 | 0 |
| done 为 1 但 reward 不为 1 | 0 |

这份数据中 `reward == 1` 与 `done == 1` 逐 transition 一致。Lift 的成功条件达到后，连续若干时间步都可能继续满足成功条件，所以一条轨迹可以在最后一个时间步之前出现多个 `done == 1`。因此 805 个“非末行 done”并不等于 805 条坏数据。

对本项目而言，`done` 更准确地表示“该时间步满足生成数据时采用的完成条件”，不能简单解释为“文件从这一行以后一定没有数据”。闭环 rollout 的成功率也不是把数据集里的 `done` 平均一下，而是让训练后的策略在新初始化环境中独立运行，再统计成功的 rollout 数量。

## 8. train/valid 划分

| mask | 轨迹数 | transition 数 |
|---|---:|---:|
| `train` | 180 | 8640 |
| `valid` | 20 | 1026 |
| `20_percent` | 40 | 1992 |
| `20_percent_train` | 36 | 1769 |
| `20_percent_valid` | 4 | 223 |
| `50_percent` | 100 | 4886 |
| `50_percent_train` | 90 | 4362 |
| `50_percent_valid` | 10 | 524 |

划分单位必须是完整 trajectory，而不是单独 transition。原因是同一条示范中相邻观测高度相似；若把一条轨迹的一部分放入训练集、另一部分放入验证集，验证集会包含训练样本的近邻，形成数据泄漏，使验证结果过于乐观。

审计确认：

- `train` 与 `valid` 的轨迹交集为 0；
- 两者并集覆盖全部 200 条轨迹；
- 20% 和 50% 子集各自的 train/valid 也互斥且能还原对应子集。

轨迹数比例和 transition 数比例不会完全相同，因为每条轨迹长度不同。例如完整 train 是 180/200，即 90% 的轨迹，但它含 8640/9666，约 89.39% 的 transitions。

## 9. 两个 Python 程序与三个报告的职责

| 文件 | 类型 | 主要问题 | 行为 |
|---|---|---|---|
| `scripts/audit_lift_ph_dataset.py` | 审计程序 | 数据能否安全进入训练？ | 检查硬性条件；失败即抛出错误并返回非零退出码 |
| `scripts/analyze_lift_ph_signals.py` | 分析程序 | 数据的动作、标记和划分呈现什么分布？ | 只读计算统计量，帮助理解数据 |
| `reports/01-dataset-info.txt` | 原始证据 | 官方工具看到了什么结构？ | 保存 `get_dataset_info.py` 的原始输出 |
| `reports/02-dataset-audit.txt` | 原始证据 | 硬性审计得到了什么结果？ | 保存审计脚本的机器可读输出 |
| `reports/03-signal-statistics.txt` | 原始证据 | 描述性统计的数值是什么？ | 保存分析脚本的机器可读输出 |
| `reports/01-dataset-audit.md` | 人类报告 | 这些证据说明什么？ | 汇总结论、概念解释和实验决策 |

换句话说：`.py` 保存可重复执行的方法，`.txt` 保存某次执行的原始结果，`.md` 保存人类能够复述和审查的结论。

## 10. 可重复执行命令

在项目根目录执行：

```bash
cd /home/lx/robomimic

# 硬性审计：任一关键条件不满足，脚本都会失败。
python reproduction/lift_ph/scripts/audit_lift_ph_dataset.py \
  --dataset datasets/lift/ph/low_dim_v15.hdf5 \
  > reproduction/lift_ph/reports/02-dataset-audit.txt

# 描述性分析：重新生成动作、reward、done 和 mask 统计。

  --dataset datasets/lift/ph/low_dim_v15.hdf5 \
  > reproduction/lift_ph/reports/03-signal-statistics.txt
```

`>` 会覆盖目标报告，因此应只在明确要重新生成报告时使用。两个脚本均以只读模式打开 HDF5，不会修改官方数据集。
